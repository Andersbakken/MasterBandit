## Terminal Protocol Support

- [x] CUP / HVP parameter conformance — `processCSI` previously rejected `\x1b[0H`, `\x1b[0;0H`, `\x1b[1;0H`, and `\x1b[1;1;1H` as `Invalid CSI CUP error 1/2/3`. ECMA-48 / xterm say "parameter value 0 is equivalent to 1" and "parameters beyond the second are ignored." mpv's `vo_kitty` hits the 0 case when edge-positioning a frame; the rejected CUP left the cursor stranded and every subsequent image landed at the wrong cell. Fix in `TerminalEmulator.cpp` CUP/HVP branch: treat `0` as the default `1`, silently discard params past the second, drop the three `sLog().error("Invalid CSI CUP error N")` paths. Tests in `test_cursor.cpp` cover zero-param single-arg / row-only / col-only / both-zero, extra-params, all-empty-params, and HVP (`f`) parity.

Now `case 1049:` in `TerminalEmulator.cpp` copies the channel-level flags (mouseMode1000/1002/1003/1006/1016, focusReporting, bracketedPaste, syncOutput, colorPreferenceReporting) from `mMainState` to `mAltState` after the reset. Tests in `test_modes.cpp` cover inheritance, no-leak-back, and the actual hover-emits-mouse-event end-to-end check.
- [x] `mpv -vo=kitty` slow / drops frames — root cause was PTY read backpressure, not allocation churn. mpv's `vo_kitty` defaults to `t=d` (`vo_kitty.c:80` `KITTY_ESC_IMG`) and ships ~5.4 MiB of base64 per 1080p frame; it sets `q=2` so it doesn't wait for any ACK. With `kReadBufferHigh = 64 KiB` (`Terminal.h:556`), each frame triggered ~85 disarm/rearm POLLIN round-trips between `readFromFD` and `maybeResumeRead`, which capped throughput to ~2.7 fps. Bumped `kReadBufferHigh` to 1 MiB and `kReadBufferLow` to 256 KiB — measured frame interval dropped well below the original ~350 ms. Per-terminal worst-case memory under a flooding producer goes from 64 KiB to 1 MiB; normal-shell coalesce stays a few KB. Diagnostic measurements: time-profile showed kitty path was 13% of CPU and `read` only ~1 ms, ruling out CPU as the bottleneck; mpv source confirmed q=2 and no auto-shm-probe; the `kitty cmd` info log (now removed) made the ~350 ms / frame interval visible.

- [x] Kill the implicit-singleton-tab-bar assumption across the JS surface, and replace int tab IDs with UUIDs. The whole "tabs are a global ordered list" model is baked into multiple APIs that break the moment a layout uses `mb.layout.createTabBar()` + `setTabBarStack()` to host more than one TabBar. Two coupled problems:
    - **Int tab IDs.** `tab.id` is a positional index into the implicit global list (`Platform_EventLoop.cpp:188` sets `ti.id = i;`), so `mb.activateTab(2)` and `tab.id == 2` have no unique meaning under multi-TabBar layouts.
    - **Singleton tab queries.** `mb.tabs`, `mb.activeTab`, `mb.layout.activeTab()`, `mb.tabBarPosition`, `tabCreated`/`tabDestroyed` events, and `mb.layout.createTab()` all assume one TabBar. `activeTab` collapses multiple per-Stack `activeChild` values to one tab; `mb.tabs` returns one merged list with no TabBar context; `mb.tabBarPosition` is one global string when the layout supports multiple TabBars at independent positions; `createTab()` appends to the implicit primary Stack with no way to target a specific Stack.

    Migration steps:
    1. **C++** — replace `TabId = int` (`ScriptEngine.h:32`) with `Uuid`; drop the positional `TabInfo::id` field; activate/close paths take UUID directly.
    2. **JS surface — narrow to UUIDs.** Remove `tab.id` (`number`); narrow `mb.activateTab` / `mb.closeTab` / `mb.layout.activateTab` / `mb.layout.closeTab` to UUIDs only; drop the `id: number` field from `mb.layout.createTab()`'s return; drop the int from `tabCreated` / `tabDestroyed` event payloads.
    3. **Add bar-relative + generic-query APIs.** Replace the singleton accessors with relational lookups composed from one generic enumeration primitive:
        - `mb.layout.queryNodes(kind: "Terminal" | "Container" | "Stack" | "TabBar", subtreeRoot?: string): string[]` — UUIDs of every node of the given kind, in tree-walk order; optional subtree scoping. One small API replacing dedicated `tabBars()` / `terminals()` / `containers()` accessors. Attribute filtering is the caller's job (`.filter(u => mb.layout.node(u).label === "foo")`) — keep the API small.
        - Per-node relational accessors via `mb.layout.node(uuid)`: TabBar gets `boundStack`; Stack gets `activeChild` and `children`; etc. (most are already in `node()`'s output — audit and fill gaps.)
        - `mb.layout.activateTabInBar(tabBarUuid, indexOrChildUuid)` — the keybinding-style "switch to tab N" use case, scoped to a specific TabBar via UUID.
    4. **Drop the singleton APIs.** `mb.tabs`, `mb.activeTab`, `mb.layout.activeTab()`, `mb.tabBarPosition` come out. They're replaced by composing `queryNodes("TabBar")` + per-TabBar lookups.
    5. **Update `default-ui.js`** to use UUIDs throughout; bar-relative addressing where it currently relies on `tab.id`.
    6. **Update `mb.d.ts`** to match.

    Visible tab-bar numbering (the `1 / 2 / 3` a user sees rendered) is purely a render-time decision per TabBar and stays as-is — display, not identity.

## Observability

- [x] `mb --ctl stats` — reports texture pool, compute pool, and per-pane GPU memory usage as JSON. Inactive tab textures are released to pool on tab switch.
- [x] Fatal-signal backtrace — `crashSignalHandler` (`src/main.cpp`) installed at the top of `main()` for `SIGSEGV`/`SIGBUS`/`SIGABRT`/`SIGILL`/`SIGFPE` before anything else (including the `--ctl` branch) so static-init and early-startup crashes still produce diagnostics. Re-raises under `SIG_DFL` so the exit status reflects the real signal and a core file gets written if `ulimit -c` permits. Shares the per-pid IPC-socket cleanup path with `cleanupSocketAndExit` via a `volatile sig_atomic_t g_socketCleanupOnExit` flag flipped on once `main()` commits to the headless/IPC code path, so the socket file is removed on either crash or graceful exit. Release builds carry `-g` and link with `-rdynamic` on non-Apple targets (see top-level `CMakeLists.txt`) so the dynamic symbol table actually resolves internal frames — without `-rdynamic` on ELF you only get `binary+0xoffset` per frame, which is useless without an offline `addr2line` pass. macOS uses `dladdr()` internally and doesn't need the flag.

- [x] Watch the shell pid for exit. Previously `Terminal::markExited` only fired on PTY master EOF/EIO, which requires every slave-side fd to be closed. Backgrounded/disowned children (zsh `foo &!; exit`) keep their slave fds open and the tab would never close — orphaned with the live shell gone. Now post-fork the parent stores `mShellPid` and watches it for exit: Linux uses `pidfd_open` + `EventLoop::watchFd(Readable)`, macOS uses a detached `waitpid` helper thread that `post()`s back to main. Both fire `markExited()` on shell death regardless of dangling slave fds. The shared-state pattern (`PidWatch` struct held via `shared_ptr`) lets the macOS helper safely outlive its Terminal: destructor flips `ownerDead` and detaches, helper observes the flag after `waitpid` returns and skips post(); the posted lambda re-checks before dereferencing. Manual repro: launch mb, run `( sleep 60 & ); exit` in zsh — tab should close immediately (was: tab stays open for 60s). Follow-up: the initial landing was latent-broken in production — `Terminal::init()` (which calls `startShellPidWatch()`) ran in `spawnTerminalForPane` before `addPtyPoll`'s `setEventLoop`, so the watch saw a null loop and silently bailed (test/headless guard taken on every spawn). `setEventLoop` now retroactively arms the watch when the shell pid is known, `startShellPidWatch` is idempotent and bails before opening kernel resources without a loop, and the Linux pidfd cb captures pid+alive-flag by value (mirroring the macOS `PidWatch.ownerDead` gate) so an async-queued FdPoller Remove that hasn't drained yet can't UAF the captured `this`. `~Terminal` now also calls `stopShellPidWatch` — previously unnecessary because the watch never armed in production.

## Architecture / Threading

Two-thread model: main thread owns the event loop, PTY reads, VT parsing, window/input, and script execution; a dedicated render thread owns GPU submission. Render reads from `TerminalSnapshot` (viewport copy) under `TerminalEmulator::mMutex` (`std::recursive_mutex`). Wakeups via `renderCv_` / `renderWake_`.

The coarse mutex, `PendingMutations`, and `RenderFrameState` shadow copy live on `RenderThread` (exposed only to `PlatformDawn` via `friend`). Main thread accumulates mutations in `renderThread_->pending()` (no lock needed — main-thread-only), then applies them in a single batch via `renderThread_->applyPendingMutations()` under `renderThread_->mutex()` at the end of each event loop tick. This rebuilds `renderThread_->renderState()` — a shadow copy of tab/pane structure, font metrics, colors, divider geometry, and pre-computed tab bar cells. The render thread (inside `RenderEngine::renderFrame`) snapshots `renderState()` into its own `frameState_` under the same mutex at frame start, then releases the lock for the remainder of the frame. All post-unlock reads go through `frameState_`; render-thread-only state lives in `RenderEngine`'s `PaneRenderPrivate` maps. Zero GPU/Dawn calls on the main thread after init. See `src/platform/RenderSync.h`, `src/platform/RenderThread.{h,cpp}`, `src/platform/RenderEngine.{h,cpp}`, `src/platform/PlatformDawn.{h,cpp}`, and `src/terminal/TerminalSnapshot.{h,cpp}`.
